# ADR 002: Events-Hash Sleep Plan Cache Invalidation

## Status
Accepted

## Context
Sleep plans are generated by the AI and persisted to `sleep_plans`. We need to know when the current plan is stale because new events were logged.

## Decision
Store an `events_hash` on each `sleep_plans` row. The hash is computed with `computeEventsHash()` over the relevant sleep events. The client/API compares the stored hash with a fresh hash of current events to determine staleness.

## Consequences

**Pros:**
- Cheap, deterministic staleness check without re-querying the AI.
- Works across clients and sessions.

**Cons:**
- Hash must be recomputed whenever events change.
- Slightly brittle to event ordering/field changes; `computeEventsHash` sorts and normalizes events to keep it stable.
