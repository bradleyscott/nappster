## Architecture Overview

Nappster is a PWA for tracking baby sleep with AI-powered recommendations. Built with Next.js 16 App Router, Supabase for auth/database/realtime, and Vercel AI SDK for OpenAI integration. The main surface is a **state-driven dashboard**; AI assistance lives in a swipe-up chat drawer.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for detailed system documentation.

## Key Patterns

### Tool-Based AI Architecture

The AI uses **tool calling** to fetch data dynamically rather than receiving pre-injected context:

```text
User message → AI decides which tools to call → Tools fetch from database → AI responds
```

Tools are defined in [src/lib/ai/tools/](src/lib/ai/tools/):

- **Read tools** (`createReadOnlyTools()`): `getBabyProfile`, `getTodayEvents`, `getSleepHistory`
- **Write tools** (added by `createChatTools()`): `createSleepEvent`, `updatePatternNotes`, `updateSleepPlan`, plus `getChatHistory`

### Deterministic State Machine

Sleep state is computed, never guessed by the AI. [src/lib/state-machine.ts](src/lib/state-machine.ts) defines four states — `awaiting_morning_wake`, `overnight_sleep`, `daytime_awake`, `daytime_napping` — with valid events and transitions from each. The dashboard (`src/components/sleep/sleep-dashboard.tsx`) derives its hero card and action buttons from the current state.

### API Routes

| Route                          | Purpose                                    |
| ------------------------------ | ------------------------------------------ |
| `POST /api/chat`               | Streaming chat with tool calling (GPT-5.2) |
| `POST /api/chat/messages`      | Paginated chat history                     |
| `GET /api/sleep-plan/[babyId]` | Fetch active sleep plan (checks staleness)   |
| `POST /api/invite`             | Generate a 6-digit caregiver invite code     |
| `POST /api/invite/redeem`      | Redeem an invite code to join a baby          |

Sleep plans are generated by the AI during chat (`updateSleepPlan` tool), not via a separate generation endpoint.

### Data Access Layer

All direct Supabase queries live in [src/lib/services/](src/lib/services/) (`sleep-events`, `sleep-plans`, `chat-messages`, `babies`, `family-members`, `invite-codes`). Components, hooks, API routes, and AI tools consume services rather than calling `supabase.from(...)` directly. Services accept an injected `SupabaseClient` so mock mode works without code changes.

### Supabase Clients

Two patterns in [src/lib/supabase/](src/lib/supabase/):

- `server.ts` - Server components and API routes (cookie-based)
- `client.ts` - Client components (browser storage)

### Database Schema

Core tables in [supabase-schema.sql](supabase-schema.sql):

- `babies` - Baby profiles with birth date and pattern notes
- `family_members` - Links users to babies (multi-caregiver support)
- `sleep_events` - Event types: `wake`, `nap_start`, `nap_end`, `bedtime`, `night_wake`
- `chat_messages` - Persisted messages with tool invocation parts
- `sleep_plans` - Generated daily schedules with cache invalidation via events hash
- `invite_codes` - 6-digit caregiver invite codes with 24-hour expiry

### Realtime Sync

Multi-user sync via Supabase Realtime in [src/lib/hooks/use-realtime-sync.ts](src/lib/hooks/use-realtime-sync.ts):

- Subscribes to `postgres_changes` on `sleep_events`, `chat_messages`, `sleep_plans`
- Uses broadcast channel workaround for DELETE events (RLS blocks postgres_changes deletes)
- Streams are merged centrally in [src/lib/merge-data.ts](src/lib/merge-data.ts) (initial + local + realtime + background-refresh)

### Event Grouping

[src/lib/sleep-utils.ts](src/lib/sleep-utils.ts) provides:

- `groupEventsIntoSessions()` - Pairs nap_start/nap_end and bedtime/wake
- `findSessionForEvent()` - Finds which session an event belongs to
- `computeEventsHash()` - djb2 hash used to invalidate cached sleep plans
- Returns `TimelineItem[]` for UI rendering

### Timezone Handling

- User timezone stored in cookie, set client-side
- Passed to API endpoints; all timestamps stored as UTC in database
- `date-fns-tz` used for timezone conversions ([src/lib/timezone.ts](src/lib/timezone.ts))

## Common Tasks

### Adding a New AI Tool

1. Create tool file in `src/lib/ai/tools/`
2. Export from `src/lib/ai/tools/index.ts`
3. Add to `createChatTools()` or `createReadOnlyTools()` as appropriate

### Adding a New Database Table

1. Add schema to `supabase-schema.sql`
2. Add RLS policies for access control (scope via `family_members`)
3. Add TypeScript types to `src/types/database.ts`
4. If realtime needed, add to publication and update `use-realtime-sync.ts`
5. Add a service module under `src/lib/services/` and consume it everywhere

### Modifying Sleep Events

- Events are paired into sessions (nap_start→nap_end, bedtime→wake)
- Quick log happens via dashboard action buttons (instant) or `EventSheet` (with time/context/notes)
- Editing uses `SleepEventDialog` for single events, `SleepSessionDialog` for pairs, and `UnifiedEditDialog` as the dispatcher
- After modification, the events hash changes and the sleep plan refreshes
